# Supplier extraction benchmark: first holdout run

**Run date:** 2026-09-30  
**Provider/model:** OpenRouter / `~z-ai/glm-flash-latest`  
**Prompt/schema:** `supplier-v2` / `commitment-v1`  
**Split:** 60 holdout examples from the synthetic 300-message benchmark

This is the first recorded end-to-end benchmark result for the current model and prompt. The predictions were scored against the checked-in gold file. The evaluator makes no additional model requests when scoring a saved predictions file.

## Results

| Measure | Result |
| --- | ---: |
| Complete examples exactly matched, including review decision | 27 / 60 (45.0%) |
| PO reference field exact match | 37 / 40 (92.5%) |
| ETA field exact match | 39 / 40 (97.5%) |
| Quantity field exact match | 37 / 40 (92.5%) |
| Business type field exact match | 19 / 40 (47.5%) |
| Gold review-required examples routed to review | 13 / 30 (43.3%) |
| Gold review-required examples accepted | 17 / 30 (56.7%) |

Field denominators include one failed provider request as an incorrect extraction, so these are conservative end-to-end field scores. The provider returned 59 structured responses out of 60 requests. One failed request produced a `REQUIRES_REVIEW` proposal.

The review denominator is 30: 20 gold rows have `expected: null`, and 10 extractable rows carry confidence `0.45`, below the application's `0.7` review threshold. “Accepted” here means a proposal was returned without a review state. Exact-record match requires the four benchmark fields to match and the review decision to match the gold expectation. Confidence calibration and evidence quality are not scored.

Token totals are omitted for this historical run: the provider adapter could retain usage metadata from the previous request if a request failed. The adapter now clears that metadata before each request, so future reports can distinguish successful responses from failures.

## How to read this result

- PO reference, ETA, and quantity fields matched the gold labels often on the 40 extractable examples.
- Review routing is not reliable yet: more than half of gold review cases were accepted without review.
- The type score is a match against the current gold labels, and those labels need review. The `date-relative-only` gold says `quantity_change` for “We expect 8 units next month, but have no confirmed ETA,” although the prompt defines `quantity_change` as an explicit comparison or revision against a baseline. The `quantity-unspecified` gold says `eta_change` for an arrival date with no prior ETA comparison, while the prompt reserves `eta_change` for a stated revision.
- This is a small synthetic benchmark made from authored templates. It does not estimate performance on real supplier emails.

The holdout has now been examined and should not be used to tune the prompt or model. Review the label taxonomy using development data, then establish a new unseen evaluation set before making another final accuracy claim. A representative set of labeled supplier messages is still needed for a real-world performance estimate.

## Reproduce the scoring

The original predictions are in the local, Git-ignored `.tmp/evaluations/` folder. To rerun the model evaluation, which makes provider requests and may incur charges:

```bash
pnpm --filter @procurebrain/api evaluate:supplier-extraction -- --split=holdout
```

To evaluate an existing predictions file without model calls:

```bash
pnpm --filter @procurebrain/ai evaluate:dataset -- /absolute/path/to/predictions.json
```

The exact historical prediction file is not published. The aggregate metrics above preserve the run result without publishing per-example model outputs as a claimed benchmark artifact.
